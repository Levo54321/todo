# luc-todo — current state and architecture

_Snapshot: 1 Nov 2026 (v1057). Repo `Levo54321/todo`, live at https://luc-todo.vercel.app._

## 1. Big picture
```
iPad 2 (iOS 9) / iPhone  --XHR-->  /api/*.js (Vercel Node, dub1)  --RPC-->  Supabase Postgres (security-definer functions)
        |                                   |--> Apple iCloud CalDAV  (api/cal.js)
        |                                   |--> Google Calendar OAuth (api/gcal.js)
        |                                   `--> Open-Meteo / iCal feed (api/glance.js)
```
Only the API layer holds the Supabase key. The browser holds the access token (localStorage) and sends it as `x-todo-token`.

## 3. Data model
`todos` (RLS on, accessed only by RPCs). Key fields: `list` personal/work; `category` is the project for Work; `prio` 0-3; flags `must`, `quick`, `low`, `blocked`, `paused`; recurrence `recur` (daily, weekdays, weekly, fortnightly, monthly, yearly) with `recur_until` and `series_id`; session tasks use `is_session` + `items` jsonb; `plan_date/plan_order` drive day planning; calendar sync fields `cal_uid/etag/sig`; `pproject_id` (nullable) links a Personal task to a Personal Project; `pp_backlog` keeps such a task on the project page only (Backlog).
Other tables: `personal_projects(id,name,status,meta,pos,created_at,updated_at)` (status idea/in_progress/live/paused/not_pursued/shut_down, 'active' accepted as in_progress; names unique ignoring case; `pos` = hand-made order, one order across all projects, new projects get min-1; `meta` jsonb: sites [urls], links [{l,u}], vercel, supabase, github, desc, reason (plain text ≤300), started, target, icon, acct_vercel/acct_supabase/acct_github (plain text ≤80)), `personal_project_events(project_id,at,kind,text)` (activity log, written by `pproj_save`, `todo_update` and the cost RPCs), `personal_project_costs(id,project_id,name,amount numeric(10,2),currency,freq monthly/yearly/one_off,next_due,link,email)` (max 30 per project, deleted with the project; returned as `costs` by `pproj_list`), `personal_project_icons(project_id pk, kind upload/site/none, mime, data base64 ≤~200 KB)` (returned as `icon_kind`/`icon_at`), `app_config(key,value)`, `budget_entries(entry_date,kind,amount)`, `saver_images`. Shop tables (`shop_*`) and the `shop` config key share the database but belong to holmlodge-shop (a separate app with its own repo/project); this app never reads or changes them.

## 4. API surface
`/api/todos` (GET list, POST add/quick-add, PATCH, DELETE; plan ordering), `/api/pause`, `/api/projects` (Work), `/api/pprojects` (Personal Projects), `/api/history`, `/api/budget`, `/api/cal`, `/api/gcal`, `/api/glance`, `/api/ics` (event, task feed, bill feed), `/api/saver`, `/api/settings`, the vault (`POST /api/pprojects?vault=1`, code in `api/_vault.js`).
Env vars (Vercel only): `SUPABASE_URL`, `SUPABASE_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`; optional `GLANCE_LAT/LON/PLACE`, `CAL_ICS_URL`, `VERCEL_TOKEN` (live deploy dots on My projects), `VAULT_PEPPER` (32+ random characters; switches the vault on; **losing or changing it makes every vault value unreadable**).

## 5. Key data flows
- **Quick add** (Shortcut or app): `POST /api/todos {text}` -> shorthand parsed server-side (days, months, times, list/category) -> `todo_add`.
- **Work ordering**: client `cmpWork` sorts the Work column; `Ot/At` maps from `setProjects` break ties by project order; board order saved via `PATCH /api/projects?id`.
- **Pause**: `POST /api/pause?id {paused,on}` -> `todo_pause`. Pausing stamps `paused_at`; resuming adds elapsed whole days to `due_date` and accumulates `paused_secs`. Paused tasks are excluded from Overdue/counts and from `todo_history` durations. Resume then best-effort re-syncs Apple/Google calendars.
- **Calendars**: personal timed tasks -> Apple CalDAV (only events with UID suffix `@luc-todo` are ever touched). Timed Work tasks -> Google Calendar when the editor choice is "yes" (per-task choice stored via `/api/gcal` `sched`).
- **Personal Projects** (v1041): separate from Work projects and from the Personal `category` label (which stays a free label driving chips/filters). `GET /api/pprojects` -> `pproj_list` (counts incl. `done_old` = finished >7 days ago, since `todo_list` only returns the last 7 days of done tasks); `POST`/`PATCH` -> `pproj_save`; task link via `PATCH /api/todos {pproject_id}` (or `POST /api/todos {title, pproject_id}`). `todo_update` keeps `pproject_id` only for Personal tasks (cleared on a move to Work) and copies it to the next copy of a repeating task. In `core.js`, `isShelved(t)` = open Personal task whose project is not Active: treated like a paused Work task (out of Overdue, badges, stats, category counts, Today's order, review nudges, Insights open/behind) and listed in a collapsed "On-hold projects" group. Rail item "My projects" sits under Personal; the Work board keeps "Projects".
- **My projects v2** (v1042): `GET /api/pprojects?deploy=1` asks the Vercel API (env `VERCEL_TOKEN`) for the latest production deploy of each project whose `meta.vercel` is `https://vercel.com/<team>/<project>`, cached ~5 min per warm function; green READY, orange building/queued, red error/cancelled/blocked, grey unknown. Saving a new site link makes the server look up the site's apple-touch-icon/icon once (stored as `meta.icon`; the browser falls back to the first letter). `GET ?events=<id>` returns the activity log. v1043: statuses In progress / Live (both count normally; shelved = paused, not_pursued, shut_down via `PP_SHELF` in core.js), several websites and labelled links, a Vercel project picker (`GET ?vercel=1` lists the token's projects; `GET ?vercel=<team>/<name>` returns production domains minus git/team aliases and redirects, plus the GitHub repo from `link`), deploy dot PAUSED (hollow ring) when the Vercel project has `paused: true` or its first website answers 503 `x-vercel-error: DEPLOYMENT_PAUSED`, and a collapsible Activity section (remembered in localStorage `ppAct`). Backlog: `inBacklog(t)` in `core.js` takes the task out of `inMode`, so it never appears in the Personal list, badges, counts, Today's order or Insights; it shows only on the project page ("→ Add to my list" / "→ Back to backlog", data-act `ppbl`). Project forms use class `ppadd` (not `bdadd`, which board.js's submit handler owns).
- **My projects layout** (v1044): wider than 760px the view is fixed-height: `pprojects.js` adds class `ppfix` to `#vPprojects`, which switches the outer `.scrollview` to `overflow:hidden`, and `layout()` sets px heights from `window.innerHeight` (never `vh`) on every paint, resize and orientation change. Board: `.bdcols` is the only sideways scroller; each open lane wraps its cards in `.pplane` (own vertical scroll). Project page: `.pptop` (All projects bar) fixed, `.ppside` frozen at full height (scrolls only if its own content is taller, e.g. Edit details), `.ppmain` is the only scrolling column. Scroll positions (lane tops, sideways offset, page columns) are kept across repaints. 760px and narrower: stacked, page scrolls as before. Vercel picker: the details draft remembers which websites (`draft.vsites`) and GitHub link (`draft.vgh`) the picker filled in; a new pick replaces those and keeps hand-typed ones (for a saved project these are worked out by asking `?vercel=` for its current project when the form opens). Icon lookup returns nothing when the site cannot be read (503/paused/timeout) and the API then keeps the stored `meta.icon`.
- **My projects v4** (v1045, `db/setup17.sql`): status **Idea** (first lane; shelved like Paused via `PP_SHELF` in core.js, but still pickable in the task editor as "(idea)"; opening an Idea project sets the add toggle to Backlog). **Reason** (`meta.reason`) is shown and edited in the Status section of the project page and on the card for Idea/Paused/Not pursued/Shut down only (kept but hidden otherwise); moving a project to one of those on its page opens the reason box if empty; `pproj_save` logs a `reason` event (text, or null = cleared) and leaves it out of "Details updated". **Still-live warning**: client-side from the `?deploy=1` dot: Paused/Not pursued/Shut down + green READY -> red banner on card and page, count in the board summary. **Order**: lanes sort by `pos`; drag the ☰ handle (touch + mouse code adapted from board.js, no HTML5 drag-and-drop; wide screens auto-scroll the lane, phones the page); drop sends `PATCH ?order=1 {ids}` -> `pproj_order`, which swaps those projects among the positions they already hold (so lane changes keep relative order). `paint()` is suppressed while a card is being dragged. v1046: the Idea lane is hidden while empty; `paint()` writes nothing when `App.setHTML` reports no change (core's 15 s refresh used to re-set field values, focus and scroll positions, which flickered on iOS 9 and moved the cursor), and a real redraw puts focus and the cursor back.
- **Project costs** (v1047, `db/setup18.sql`): "Subscriptions and costs" section in the project page's side panel (add/edit inline, delete with a confirm). Monthly/yearly due dates roll forward in the browser from the stored date (`dueOf`, day-of-month kept); one-offs keep their date and show Overdue once passed. Cards show the soonest cost due within 30 days (or an overdue one-off). Totals per currency: monthly + yearly/12 as "a month · a year", one-offs separately. Budget's bills are not reused (they live in the `budget` config, monthly GBP, no ids); the page reads `GET /api/budget` once to show "also in Budget" when a cost's name matches a bill. API: `POST ?cost=1`, `PATCH ?cost=<id>`, `DELETE ?cost=<id>` -> `pcost_save` / `pcost_delete`, which log `cost_added/changed/removed` events.
- **Accounts and icons** (v1048, `db/setup19.sql`): Edit details has Vercel/Supabase/GitHub account labels (shown as an Accounts section; the Vercel picker fills the team and GitHub owner when empty) and icon controls. Card logo source: stored icon (`/api/pprojects?icon=<id>&v=<icon_at>&t=<token>`, served with `nosniff` + `sandbox` CSP) > `meta.icon` link > first letter. Uploads are centre-cropped to a 128px PNG in the browser (canvas, like saver.js). "From website" stores a copy of the site's icon (fails with a clear message when the site is paused/down); "Remove" stores kind `none` = letter, and stops automatic site copies. Saving details also stores a site copy when a new icon is found or none is stored yet. Images are checked by magic bytes (PNG/JPEG/GIF/ICO/WebP; never SVG). `saveDetails` keeps `meta.reason` (meta is replaced whole; v1047 and earlier dropped the reason on a details save).
- **Token and shared loads** (v1050): modules that need the token call `App.whenToken(fn)` (runs at once, or as soon as the token is typed at the gate; no more give-up after 8 tries). `App.getProjects(cb)` is one shared `GET /api/projects`; concurrent callers (Work board, Manage Projects) share one request. Work board `paint()` writes scroll positions only when `setHTML` really changed the DOM; a failed first load shows "Could not load your projects" with Try again (`data-bd=retry`). The My projects page owns `#viewTitle` (core does not write it for that view).
- **Polling** (v1052): the app asks "has anything changed?" instead of downloading the list every time. `GET /api/todos` returns `{today, now, v, todos}`, where `v` is a 20-character SHA-1 fingerprint of the `todo_list` result (not of `now`). `GET /api/todos?v=<v>` answers `{same:true, today, now}` (about 70 bytes) when the list still hashes to `v`; without `?v=` (older cached apps, Shortcuts, the `?open=latest` check in `shell.html`) it is the full list as before. In `core.js`, `load()` remembers the last `v` (`lastV`) and the `lastMutation` it belongs to (`vMut`) and sends `?v=` only while they still match, so any local edit (which sets `lastMutation`) makes the next refresh a full one; if a full list arrives inside the 2.5 s edit guard it is not taken in and `lastV` is cleared. Paths that mean "refresh and trust the server" (failed save/delete, closing the review, a repeat's next copy, calendar changes, `App.reload()`) go through `forceLoad()`, which also clears `lastV`. On `same`, `todos` is kept, `today`/`serverOffset` are updated, and `render()` runs only if the app was offline or not yet loaded, the day changed, or the minute moved on (the glance strip greys events that have ended and the "new" quick-chips expire by the clock; the redraw is local and `setHTML` writes nothing when the markup is unchanged). Refresh runs every 30 s in the foreground (focus, resume, `pageshow`, visibility changes and after-edit refreshes are still immediate); idle (screensaver) is every 10 minutes (20 ticks). Apple calendar sync (`maybeCalSync`) is at most every 5 minutes (`CAL_EVERY`), retry after a failure ~30 s. Measured with `docs/audit-2026-11/scripts/audit_calls.py` on mock data (109 rows, ~80 KB per full list), one hour, Personal list open: calls 246 → 126, data 19.1 MB → 8 KB; with Apple calendar on 276 → 138.
- **Google sign-in** (v1051): the app does `POST /api/gcal {start:true}` (token in the header) and navigates to the returned Google address; `state` is AES-GCM encrypted (10 min), so the token is never in a sign-in link. `GET ?action=start` is retired (410). `#t=` in the address is read once and removed. `?t=` is still accepted on every endpoint because Luc's iPhone Shortcuts use it (tabled, revisit with rotation).
- **Vault** (v1049, `db/setup20.sql`, `api/_vault.js` reached via `POST /api/pprojects?vault=1`): per-project sensitive values behind one vault password (separate from the access token, set on first use). All crypto is server-side in Node: key = HKDF-SHA256(scrypt(password, salt; N=2^15, r=8, p=1), VAULT_PEPPER); names and values are each AES-256-GCM with a random IV and AAD `name|value:<project>:<entry id>`. The database holds only `pvault_lock` (salt, kdf, check blob, fails, lockout) and `pvault_entries` (ciphertext). Unlock returns a pass (the key sealed with a pepper-derived key, 5-minute expiry, renewed by every call) that the page keeps only in a JS variable; the page drops it after 5 idle minutes, on Back, another project, leaving My projects, the app going to the background and pagehide. Locked state returns only a count. 5 wrong passwords lock for 5 minutes. Everything is POST (nothing in URLs); no activity events; errors log only a code. Forgotten password = "Wipe vault" (type DELETE ALL), which deletes every entry. iOS 9 cannot copy from script: Copy falls back to showing the value selected so a tap on "Copy" works.
- **Shopping**: removed from this app on 1 Nov 2026 (v1040). The list lives only in holmlodge-shop.vercel.app.

## 7. Known nuances
- **Vault safety (honest)**: safe against a copy of the database alone (shop app included): it holds only ciphertext, and opening it needs both the vault password and `VAULT_PEPPER`. Someone with luc-todo's Vercel env (pepper) *and* the database could try passwords offline, slowed by scrypt, so use a long passphrase. It is server-side encryption, not end-to-end: values are decrypted in the Vercel function (over TLS), so Vercel/whoever controls the deployment could read them. Anyone holding the access token can wipe the vault but cannot read it. Not a replacement for a password manager for your most critical secrets.
- **Config keys are whitelisted** in `cfg_get`/`cfg_set` (`db/setup13.sql`): budget, caldav, caldav_state, saver, shop, gcal, projects. A new key needs a migration that edits both lists.
- `todos.category` (the project name) is capped at 40 characters; `title` at 500.
- `todos.created_at/updated_at` predate `db/setup01.sql`; rebuilding the database from `db/` alone would need the base `todos` table first.
- `todo_update` does not clear `paused` when a task is marked done (history handles it); check board/list code if a done task ever shows as paused.
- `db/setup01.sql` holds a placeholder for the access-token hash. Never commit the real hash.
- Repo `public/js` is readable source; earlier manual deploys were terser-minified. Cache buster `?v=` must be bumped in `build.py` args when JS/CSS change.
- Vercel MCP file-content reads truncate at ~2 KB; get source from the repo instead.
- Pause/Blocked/board features are mock-tested only; not yet exercised on physical iPad 2.
- Icons for sites that were already paused before v1048 cannot be copied (the site will not answer); upload one instead.
- The Work board's lane lists still use `max-height: calc(100vh - 290px)`; My projects no longer does (JS heights).
- Test folders (t8-t12), old index versions and `.token` are intentionally not in the repo.
- Time zone is fixed to Europe/London in `api/todos.js`.
- **Design system (v1056/57)**: see CLAUDE.md "Design" and Pitfalls (44px chips via transparent border, `background-color` not `background`). Meta line on task rows: categories and states are pills, time/repeat plain text. Phone: header compact, Glance and category filters scroll sideways, bottom bar icon-only. Board rows mark state with a 3-4px edge bar (blocked red, due today amber, high priority accent, paused grey) instead of tinted rows. The Work board lists still use `max-height: calc(100vh - 290px)`.
- **Navigation and look (v1053)**: rail = Personal, Work, Projects, Tomorrow, Budget, Insights, Settings (no Workouts). `Projects` (`#nProjects`) is shown once `board` or `pprojects` registers; `navTo('projects')` opens the Work board from the Work list and My projects from the Personal list, otherwise the last choice (`projMode`). The Work | Personal switch lives in the header (`#projSwitch`, visible only when `body[data-view]` is `board`/`pprojects`). Phone (<700px): icon-only bottom bar, compact header (hint hidden), My projects lanes reordered by CSS `order` (In progress, Idea, rest). Styling: tokens at the top of `app.css` plus the "v1053 premium layer" block at its end; board and My projects CSS now live in `work.css` / `pprojects.css` (v1054, audit W8 done).

Any invalid row means nothing is added. After an import `App.reloadWhenSettingsClose()` refreshes the list when Settings closes (`load()` is paused while Settings is open). The schema and column guide for users are in `docs/import/` (`luc-todo-import.schema.json`, `luc-todo-import-columns.csv`); keep them, `_bulk.js` and `TEMPLATE` in `csvimport.js` in step.
